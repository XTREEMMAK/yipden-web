# n8n runbook: "Is this you?" requests

The form at `/is-this-you/` posts to n8n, which checks the request, keeps it in a Data Table, and
sends you a Gotify notification with a signed review link. Nothing is automatic: a removal reaches
the directory only when you approve it. The workflows are generated by
[scripts/n8n/build_workflows.py](../scripts/n8n/build_workflows.py), modelled on indienodes-app's
generator. Edit the generator, never the workflows in the n8n UI: the next push overwrites them.

| Workflow                                  | What it does                                                        |
| ----------------------------------------- | ------------------------------------------------------------------- |
| `YipDen - Error Workflow`                 | Records which node failed. Never a request's words or address.      |
| `YipDen - Helper - Review Link Signature` | Signs and verifies review links (HMAC-SHA256, 7 days).              |
| `YipDen - Directory Request`              | The form's webhook: bot gate, Turnstile, rate limit, store, notify. |
| `YipDen - Directory Review`               | The review page; Approve and Reject are POSTs from that page.       |

## One-time setup

1. **Credentials** in n8n, with exactly these names:
   - `YipDen - Review Link HMAC`: type _Crypto_, a long random secret (`openssl rand -hex 32`).
   - `YipDen - Rate Limit Salt`: type _Crypto_, a different random secret. It hashes IPs, so no IP is stored.
   - `YipDen - Turnstile Secret`: type _Custom Auth_, with
     `{"body": {"secret": "<Turnstile secret key>"}}`.
   - `YipDen Notifications`: type _Gotify_, the server URL and an application token.
   - `Github PAT - YipDen`: type _Header Auth_, name `Authorization`, value `Bearer <token>`. Use a
     fine-grained token for `XTREEMMAK/yipden-app` only, with **Actions: read and write**. That is
     all it needs: it can start the opt-out workflow and nothing else.
2. In yipden-app on GitHub: _Settings → Actions → General → Workflow permissions_, tick **Allow
   GitHub Actions to create and approve pull requests**. Without it the opt-out run cannot open
   its pull request.
3. Paste each credential's id into the `*_CREDENTIAL` dicts at the top of `build_workflows.py`. The
   id is the last part of the credential's URL in n8n.
4. `python3 scripts/n8n/build_workflows.py --create-tables`, and paste the two printed ids into
   `TABLE_REQUESTS` and `TABLE_RATE_LIMITS`. The columns are in
   [data-tables-schema.json](../scripts/n8n/data-tables-schema.json).
5. `python3 scripts/n8n/build_workflows.py --push`. It refuses while any id above is missing. The
   API key is read from `~/.n8n-api-key`, the same file indienodes-app uses.
6. In n8n, **activate** `YipDen - Directory Request` and `YipDen - Directory Review` by hand. The push
   only publishes the signature helper, because it has no public trigger.
7. Build the site with both build args, then redeploy:
   ```bash
   REMOVAL_WEBHOOK_URL=https://n8n.kjnet.us/webhook/yipden-directory-request \
   TURNSTILE_SITE_KEY=<site key> docker compose up -d --build
   ```
   The Turnstile widget's hostname list must include `yipden.com`.

## Handling a request

The Gotify message names the request, the listing, any entry id and the reply address, and ends
with a **Review** link. Opening it only shows the request; nothing changes until you press a button.

- **Remove with an entry id** → Approve dispatches yipden-app's `directory-optout` workflow with
  that id alone. It hashes every form of the person into `optouts.json`, removes the entry, and
  opens a pull request. **Merge it**; the app drops them on its next check. If GitHub refuses, the
  request is marked `approval_failed` and the same link works again once the token is fixed.
- **Remove without an id, Correct, Confirm** → Approve marks it done, and the page says the one
  step that is yours (`pnpm directory:optout <address>`, an edit to `people.json`, or
  `"listing": "confirmed"`). Check a confirmation really is them before you set it.
- **Reject** → nothing changes in the directory.

Any decision clears the request's contact address and details from the table. Reply to the person
first if you mean to. A link expires after 7 days: open the request's row in the table and ask
n8n for a fresh link, or handle it by hand from the row.

## Checks the request workflow makes

A filled honeypot or a send under 1.5 s gets the same `{ "ok": true }` as a person and is dropped.
Then Turnstile, which fails closed. Then one request per IP every 10 minutes, though a **removal is
never held back**. Then the request is stored and you are notified. A failed notification still
leaves the request in the table. n8n keeps no execution history for these workflows, so a request's
words live only in the table.
